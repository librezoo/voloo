# v0.7.5 — Reliable rollback replies

Fixes `voloo firmware rollback` sometimes reporting "Connection reset by peer" (outcome
unknown) although the rollback had completed: the background process did not read the
request body, so a body arriving after the reply caused a TCP reset that could discard it.
The daemon now always reads the body and the client sends each request in one write.

Firmware 3.3.0 and the firmware manifest are unchanged; `voloo firmware update` keeps
reading `voloo.librezoo.com/firmware/x035/manifest.json`.

```sh
npm install -g @librezoo/voloo@0.7.5
voloo daemon stop
```

Validated on a real board (CD-AB-70-F3-69-BE-A6-5D): CLI write regression 45/45, HTTP/MCP
latency run, six consecutive rollbacks without a reset (3.3 and 3.2 alternating, ending on 3.3).
